# CyberFurry WebAR Demo

面向 Android Chrome / ARCore 的 WebXR VRM 角色演示，也可在桌面与普通移动浏览器中使用同一套角色控制，在非 AR 地图内体验动作、行为和寻路。生产版本需要先选择本地 VRM；关节测试角色仅在开发模式提供，不进入生产构建。部分代码由 AI 开发。

## 运行与验证

```bash
npm install
npm run dev
```

浏览器访问终端输出的地址。构建、自动化测试及预览：

```bash
npm run build
npm test
npm run preview
```

`npm test` 使用 Node 内置测试运行器与 `tests/register.mjs` 中的 TypeScript 加载器，需要 Node.js **22.15 或更高版本**。测试覆盖寻路、行为、碰撞/移动控制、程序化骨骼动作与材质兼容等逻辑；模拟测试不等于浏览器渲染或 AR 真机验证。浏览器验收记录见 [`docs/browser-qa.md`](docs/browser-qa.md)；AR 真机验收尚未进行。

构建结果输出到 `public/`，该目录可作为静态站点部署。生成的 JS/CSS 位于 `public/assets/app/`；已有的 `public/config/` 和 `public/assets/animation/` 会保留。

## 预览操作

| 操作 | 用法 |
| --- | --- |
| 角色移动 | 左下摇杆或键盘方向键，按相机水平朝向移动 |
| 相机移动 | WASD 前后左右，Q/E 下降/上升，拖动画面转向 |
| 设置一次性目标 | 非 AR 场景双击可站立表面；也可将中央光标对准表面后点击“走到光标点” |
| 放置角色 | “放置角色 / 锁定锚点”把角色放到中央光标处；AR 下尝试创建 Anchor |
| Gizmo 平移 | 非 AR 下勾选“Gizmo 移动角色”，拖动世界坐标三轴或平面手柄；可启用 0.25 m 网格吸附 |
| 拖动恢复 | Esc 取消正在进行的拖动；“撤销上次拖动”恢复上一位置 |
| 动作观察 | “聚焦角色”调整观察角度，暂停与慢放用于检查动作 |
| 程序动作上下起伏 | 默认关闭。勾选后恢复程序动作的周期性身体升降，VRMA 使用原动画 |
| 环绕跟拍 | 角色移动时保留观察角度和距离，拖动环绕，滚轮缩放 |
| 第一人称 | 从 VRM 头部前方观察，拖动可低头查看身体，滑块调整前移和抬高 |
| 双臂外展偏移 | 用 0–40° 滑块调整两侧上臂，适用于程序步态和 VRMA 播放 |
| 停止任务 | 取消当前自主行为和演示路线，回到手动控制 |
| 跳跃 | 点击右下“跳跃”；角色必须已着地 |
| 调试 | 调整碰撞胶囊、基础移动速度、曝光、旧版材质兼容，并显示碰撞几何 |

Gizmo 拖动暂停物理与任务推进，保留行为、目标和路线；松开后从新位置重新寻路，恢复落地检测。摇杆与方向键可临时接管移动，松开后继续原任务。进入 AR 时 Gizmo 自动停用。键盘焦点位于输入框、下拉框或按钮时，不拦截其按键操作。

移动速度允许设置为 **0 m/s**，此时停止角色自主位移，暂停巡展计时；恢复正值后可继续。滑块设置的是基础速度，不同步态会乘以各自动作的速度系数。待机呼吸、重力、手动跳跃及独立 VRMA 播放不属于该速度的暂停范围。

可选择本地 `.vrm`，或包含 VRM 扩展的 `.glb`。普通无 VRM 人形信息的 GLB 不作为角色载入。`npm run dev` 中提供带独立肘、膝、踝、脚趾关节的开发测试角色；`npm run build` 会排除该实现与入口。角色与动画文件只在当前浏览器内读取，不会上传。

## 两种抵达目标的方法

“运动控制”与“角色行为”独立：行为决定去哪里，运动控制决定如何抵达。移动到目标、跟随目标、跟随玩家以及巡逻等地面任务都使用所选方式。

- **寻路模式**：对当前碰撞表面采样，使用分帧 A* 搜索有地面支撑、台阶高度可通过且胶囊空间足够的路径。避开墙体、不可通过的窄缝和缺少支撑的区域。非 AR 下显示规划路径；目标或环境变化时重新检查与规划。
- **移动模式**：朝目标沿直线移动，不规划绕行路径。仍执行碰撞与重力，遇墙会受阻；目标不会因受阻超时被替换或瞬移完成。

摇杆与方向键属于直接操纵，不会自动替玩家绕障。梯子与泳池演示采用预设三维路线：它们展示对应动作与垂直/水面运动，不是自动发现梯子、抓握梯级或生成水下路径的系统。

寻路是有限范围内的动态网格采样，不是整张地图的烘焙导航网格。网格间距约 0.22–0.45 m，搜索区域半宽最多 28 m，最多检查 6,500 个节点，并限制每帧工作量。超远目标、复杂多层结构、过窄通道和不完整的 AR 深度面可能没有可达结果；界面会显示原因。变化的环境会触发重新验证，但不能替代高精度连续碰撞或真实房间重建。

## 15 种行为

| 行为 | 表现 |
| --- | --- |
| 手动控制 | 使用摇杆或方向键 |
| 跟随玩家 | 跟随相机，保持配置的距离 |
| 跟随目标点 | 持续追踪当前有效的中央光标 |
| 移动到目标点 | 保存选定位置，抵达后停止 |
| 随机巡逻 | 在出发点附近选择路点，抵达后停留观察 |
| 四点巡逻 | 围绕出发点循环访问四个路点 |
| 漫步探索 | 缓慢改变前进方向，交替行走与休息 |
| 环绕目标 | 围绕启用时的目标点巡游，没有目标时使用出发点 |
| 八字巡游 | 沿八字形路点连续转弯 |
| 保持距离 | 玩家靠近时退避，达到安全距离后停下 |
| 接近与退避 | 接近玩家、停留观察、退回远处，循环往返 |
| 定点守卫 | 有玩家靠近时查看，玩家离开后返回岗位 |
| 往返踱步 | 在出发点两侧往返，端点停顿 |
| 侧方伴行 | 根据玩家移动方向，保持侧后方位置 |
| 扩圈搜索 | 逐圈访问周边路点，然后返回中心重新搜索 |

切换行为会以角色当前位置重新建立出发点。相机即非 AR 演示中的“玩家”；可用 WASD/QE 移动相机，观察跟随、守卫和退避反应。

## Locomotion 动作

| 动作 | 主要细节 |
| --- | --- |
| 默认 | 播放配置的 VRMA 待机、行走与跳跃片段，片段缺失时使用程序化动作 |
| 自然步行 | 脚跟落地、脚尖蹬离、骨盆侧摆与反向摆臂 |
| 跑步 | 前倾、屈肘摆臂、后腿回收 |
| 冲刺 | 大步幅、抬膝与更有力的蹬伸 |
| 潜行 | 前倾，低重心保持平稳，跨步轻落 |
| 蹲行 | 持续屈髋屈膝、踝关节补偿 |
| 四肢爬行 | 对侧手脚交替推进，手掌向后支撑并向前回收 |
| 攀爬梯子 | 手指朝上、掌面朝梯，交替伸手拉升 |
| 上楼梯 | 高抬脚越阶，根据脚下实际踏面落脚 |
| 下楼梯 | 探脚落到较低踏面，支撑腿屈膝缓冲 |
| 后退 | 短步后撤，胸肩、颈和头共同回望 |
| 向左侧移 / 向右侧移 | 两种镜像并步，领步腿与跟随腿配合 |
| 双脚跳行 | 同步预蹲、伸展、落地屈膝 |
| 自由泳 | 水平俯卧、躯干滚转、曲肘划水和交替打腿 |
| 平衡木 | 双臂展开、中线落脚、躯干微调 |
| 高抬腿 | 大幅抬膝与对侧屈肘前摆 |
| 踮脚 | 提踵、前脚掌支撑、脚趾补偿 |
| 涉水 | 高抬脚与缓慢落脚、手臂辅助平衡 |
| 滑步 | 侧后蹬伸、屈膝滑行、侧向重心转移 |
| 跛行 | 不对称步幅与支撑、肩髋补偿 |
| 律动步 | 交替踏步、肩髋反向扭转、肘腕律动 |

此外包含待机呼吸、离地收腿和落地压缩缓冲。程序动画操纵标准化 VRM 人形骨骼，包括髋、脊柱、胸、头、上/下臂、手、上/下腿、脚与脚趾，并使用四元数平滑切换。缺少可选骨骼时跳过该关节。潜行、蹲行、爬行等会同步调整用于碰撞的有效高度。

地面步态根据腿长计算支撑/摆动脚轨迹，使用二段腿部求解控制髋、膝与踝，并平滑调整骨盆高度。动画按期望速度推进；受阻、寻路失败或暂时失去跟随目标不会切到待机，正常抵达、行为停留及零速度仍可待机。骨架休息朝向用于适配 VRM 0 与 VRM 1 的局部坐标差异。

脚部 IK 在程序化动作或 VRMA 播放之后执行。脚掌会探测附近可支撑的场景碰撞面，按踏面高度和法线调整腿部与脚掌姿态。摆动脚保留抬脚轨迹，脚的水平移动随动画播放。

## 同地图演示

1. 选择本地 VRM，选择“同地图特色场景”中的项目，点击“演示此场景”。角色与相机会转移到对应区域，自动选择适合的动作并开始演示。
2. 在中央广场查看步行、高抬腿与律动；林间跑道查看跑步与冲刺；多向练习场查看后退、左右侧移与滑步。
3. 选择观景台楼梯、瞭望梯、低矮隧道、矮门、花箱掩体、静音步道、康复步道、湿地泳池、独木桥或溪畔跳石，检查不同动作细节。
4. 选择“绕障 · 寻路迷宫”，分别使用寻路模式和移动模式启动演示，比较自动绕墙与直线受阻。手动行为也可在同张地图上运行。
5. 点击“全部巡展”按场景列表自动轮换，再点击停止巡展。拖动 Gizmo 时巡展暂停计时，结束拖动后继续；显式更换行为或停止任务可结束巡展。速度为 0 时巡展等待恢复。

开始场景演示会停止正在播放的本地 VRMA，确保能观察该场景对应的程序动作。演示地图、巡展和 Gizmo 仅用于非 AR 预览；进入 AR 后隐藏地图并取消当前演示任务。

## VRMA 动画优先级

导入 VRM 后，点击“打开 VRMA 动画”选择本地 `.vrma`，可循环播放、暂停、继续和停止。**显式 VRMA 预览优先于 Locomotion 程序动作**，预览期间仍能移动与放置角色；改变步态不会覆盖正在预览的片段。停止预览后恢复当前步态对应的动作；更换角色会清除预览。无效文件会报告错误，并保留已有的有效预览。

默认动画路径：

```text
public/assets/animation/idle.vrma
public/assets/animation/walk.vrma
public/assets/animation/jump.vrma
```

自然步行风格优先使用成功载入的 idle/walk/jump 默认片段；其他风格使用程序动画。默认片段缺失或载入失败时回退到程序动画。配置位于 [`public/config/character.json`](public/config/character.json)。

## 旧版 VRM 泛白修复

对比提供的原版与带 `test` 的角色，关键区别是 **MToon 阴影贴图 `_ShadeTexture`**：原版三个材质均缺少此项；test 版依次使用纹理索引 `0`、`1`、`2`，与各自的 `_MainTex` 对应。两版 `_ShadeColor` 相同。缺失阴影贴图会使阴影侧使用白色纹理采样，再与阴影颜色相乘，因而失去主贴图的毛色与纹理细节，产生泛白观感。

其他差异包括 `_BumpScale` 从 `1.9` 改为 `1`，以及 MToon 版本字段从 `38` 改为 `39`。在未提供法线贴图的这些材质上，BumpScale 不是这次泛白的原因；兼容处理针对实际缺失的阴影贴图，而不是批量改写版本号或压暗颜色。

默认开启的“修复旧版 VRM 缺失阴影贴图”仅针对 **VRM 0.x、存在主贴图、且没有明确阴影贴图** 的 MToon 材质，将主贴图作为阴影纹理回退。保留原始阴影颜色、发光等参数，不修改已指定阴影贴图的材质，也不修改 VRM 1 材质。调试面板会显示处理数量；取消勾选可恢复原始缺失贴图状态并现场比较。曝光可单独调整，但不替代这一材质修复。

## Android AR 与深度碰撞

需要支持 ARCore 的 Android 设备、可用的 Chrome/Google Play Services for AR，以及安全上下文。正式部署使用有效 HTTPS；局域网普通 HTTP 地址无法启动 WebXR。USB 开发可使用：

```bash
adb reverse tcp:5173 tcp:5173
```

然后在手机 Chrome 打开 `http://localhost:5173`。启动 AR 后移动设备扫描环境，将中央光标对准地面，再放置角色。Hit Test 是启动所需能力，Anchors、Plane Detection、CPU Depth Sensing 等作为可选能力请求，实际开放情况由设备与浏览器决定。

CPU 深度图会被降采样并反投影为三角网格，用于角色碰撞探测与深度遮挡。相邻采样点深度差过大时不生成面片。参数位于 `environment.depthMesh`：

- `sampleColumns` / `sampleRows`：采样分辨率。
- `updateIntervalMilliseconds`：更新间隔。
- `maximumDepthMeters`：最大有效距离。
- `maximumEdgeDeltaMeters`：允许连接的相邻深度差。

深度不可用时使用检测到的平面；只有 Hit Test 时，可在放置点创建有限大小的地板代理。没有可用 WebXR 时继续使用非 AR 地图。深度与平面能力、噪声、更新延迟和表面空洞都会影响碰撞与寻路；这不是持久化房间重建或完整刚体物理引擎。
